# 裂纹快速语义分割技术路线

更新：2026-11-17。本文定义当前实施协议、模型和验证门槛。结果以[项目状态](project_status.md)和原始JSON为准，历史与停止原因见[实验记录](experiment_log.md)。参考：[飞书原始讨论](https://zcnl6gnomk0m.feishu.cn/wiki/QvQ0wcebmiVlqakop4AcA1vEniR)、[飞书技术方案](https://zcnl6gnomk0m.feishu.cn/docx/HGKSdYgM0obyLaxh4zWcnkK6nQc)。

## 研究目标与当前决策

目标是在保留细裂纹召回和几何分析所需细节的条件下，减少高分辨率完整画面的分割计算。两级结构本身不构成创新或提速证据；必须与同一轻量二级模型的全覆盖路径比较，把一级漏检、数据搬运及调度开销全部计入。

当前实施路线是**固定3×4网格候选选择 → 原像素512×512精细分割 → 2048×1536坐标重建**。保留grid（1,297,761参数）作为第一层对照、refine（1,284,689参数）作为第二层候选，质量基线使用eager FP32（训练/测速配置允许TF32）。单框、粗掩膜、多尺度任意框和若干排序适配已试验并停止。最新evidence也已完成正式训练并停止，不再列作待实现方案。

低分辨率预览、旋转框、重叠ROI、几何测量和端侧部署属于待验证扩展，不能写成当前已实现流程。项目处于主机实验阶段，尚未完成独立泛化或部署验收。

## 数据契约与空间坐标

### 原始样本和分组

1536张512×512图像恰好组成128组连续画面。组名取文件名最后切块后缀之前的完整前缀，例如 `TB_Camera4_001532`；每组固定12块：

```text
A B C D
E F G H
I L M N
```

尺寸按宽×高表示。以整图左上角为原点，x向右、y向下；列c=0…3、行r=0…2，块占半开区域 `[512c,512(c+1)) × [512r,512(r+1))`。A–D、E–H、I/L/M/N分别对应r=0、1、2。图像和原始多类别掩膜按同样坐标无缩放拼接，得到2048×1536。代码契约在 `src/tile_geometry.py`；拼接入口为 `scripts/stitch_tack.py`。

按源图组固定种子42划分90/25/13组，二级样本1080/300/156张；阳性切块196/43/24张，完整画面阳性82/20/13张、阴性8/5/0张。清单随数据保存在 `data/processed/TACK_Tunnel_B/manifest.json` 和 `full_frames/manifest.json`。不重新随机拆分切块，不跨集合拼图，不修改原始数据与标签。

标注值40为裂纹，0（背景）、160（水渍）、200（析出物）均为非裂纹。图像按RGB加载、转float并除以255；ImageNet mean/std在模型内部使用。训练集裂纹像素占比约0.0884%，阳性切块最少仅2个标注像素，低分辨率下采样容易损失证据。自动小目标/接缝筛选不构成删标依据。

### 训练与推理尺度

二级始终使用512×512原始块训练。整图推理表示系统输入2048×1536，当前通过12个原始块进行一级评分和二级选择性计算；二级没有直接进行一次2048×1536前向，也没有将整图缩成512×512后分割。

一级grid训练样本是完整画面组，张量为 `B×12×3×512×512`；推理也读取同样12块。它保留细节，同时付出全部12块轻量编码的成本，因此“只分割6块”不等于系统计算量或延迟减半。

### 增强与泄漏约束

二级训练使用同步水平镜像（概率0.5）及等概率0/90/180/270度旋转；图像与掩膜保持对应，无缩放/裁剪/插值。一级对完整画面水平镜像，再同步重排3×4块与标签；不能逐块镜像而保持块位置不动。整图90度旋转会改变3×4几何，当前一级未使用。

历史部分排序器曾使用逐块镜像，现已修正数据入口，但旧权重未因此自动重训。旧权重继续保留作历史对照，不能把相关实验失败全部归因为结构。Utility标签来自冻结二级的未增强输出，未重算标签时禁用增强。

同组切块已隔离，但相邻采集帧和不同相机之间的场景重叠尚未全面排查。现test已反复用于开发，统一称“测试开发集”；最终泛化结论必须新增独立留出数据，不能通过改名称恢复盲测资格。

## 第一层：固定几何候选选择器

### 当前保留的grid结构

实现：`src/dynamic_roi.py::MobileNetV3SmallGridRanker`；权重：`outputs/runs/dynamic_roi_grid_v1/best.pt`。早期 `dynamic_roi_mobilenetv3_small_v1` 是特征拼接MLP架构，不可混用其权重。

| 模块 | 张量/操作 | 作用 |
| --- | --- | --- |
| 共享编码器 | B×12块展开为12B，MobileNetV3-Small features；512输入末端为576×16×16 | 所有块共享参数，使用ImageNet V1预训练 |
| 全局证据 | 全局avg与max各576维，拼接为1152维 | 同时保留整体纹理和局部强响应 |
| 块投影 | Linear 1152→128，ReLU，Dropout0.1 | 每块一个128维表示 |
| 网格恢复 | B×128×3×4，加可学习1×128×3×4位置编码 | 保留块位置 |
| 邻域上下文 | Conv3×3 128→128 + BN/ReLU，再Conv3×3 128→64 + BN/ReLU | 两层普通3×3卷积，含对角邻域，并非四邻域专用算子 |
| 候选头 | Conv1×1 64→1，展平B×12 logits | 输出块分数，不输出精确边界或任意框 |

监督 `y_i = 1[原始块mask==40的像素数>0]`，在原分辨率标签上构造，不能从缩小掩膜重新判断阳性。默认按logit排序选top-6；sigmoid不改变排序，固定top-k不等于校准的图像级阴性概率。

### 当前训练入口的明确设置

`scripts/train_dynamic_roi.py` 当前支持 `--arch grid|shallow|evidence`。训练按完整画面阳性/阴性分组做带放回加权采样，期望组级1:1，每轮90组，batch=4；不等于块级正负1:1。Adam学习率1e-3，默认30轮，不使用二级的冻结编码器/早停规则。按验证top-6阳性块Recall最高值保存best；并列时保留先前权重。

损失为加权BCEWithLogits：每batch的 `pos_weight=clamp(负块数/max(正块数,1),1,12)`。默认pairwise权重0；可选成对正负排序损失是已失败的历史消融，不作为当前新增计划。训练入口保存best、history和metrics，尚未像二级一样自动保存完整config/train.log，复现实验需额外记录命令和代码版本，不能声称所有历史一级目录都有完整配置快照。

### evidence V1.1：已实施并停止

多阶段通道为24、40、96、576，均做全局avg/max，得到1472维；额外保留1/8特征（24×64×64）的2×2局部avg/max，共192维。evidence共1,363,297参数，合并1664维后投影到128，沿用3×4位置编码、两层3×3邻域卷积和候选头。该变化用于检验“块内全局池化丢失极细局部证据”的假设，不改变标签、top-k及冻结二级。

smoke只验证流程；正式30轮训练最佳第10轮，验证/测试开发块级top-6 Recall为83.72%/75.00%，低于grid的86.05%/91.67%。冻结refine后候选像素覆盖降至90.34%/85.13%，整图Recall降至53.52%/42.54%；停止局部池化路径。不能写“块级召回提高”或“延迟更高”：已有报告中其平均延迟92.44/91.84ms低于历史grid的94.79/102.20ms，但非同会话测量，不据此主张稳定提速。停止依据是质量与候选覆盖不足。

## 第二层：轻量精细分割与refine适配

实现：`src/mobilenet_unet.py`。MobileNetV3-Large编码器使用官方ImageNet V2预训练，分类头不参与；保留五级skip特征。解码器和细化块随机初始化。

| 阶段 | 通道×高×宽（512输入） | 解码操作 |
| --- | --- | --- |
| 编码1/2 | 16×256×256 | 浅层skip |
| 编码1/4 | 24×128×128 | skip |
| 编码1/8 | 40×64×64 | skip |
| 编码1/16 | 80×32×32 | skip |
| 编码1/32 | 160×16×16 | 最深层输入 |
| 解码1/16 | 96×32×32 | 双线性上采样，与80通道skip拼接，SeparableBlock(240,96) |
| 解码1/8 | 64×64×64 | 与40通道skip拼接，SeparableBlock(136,64) |
| 解码1/4 | 40×128×128 | 与24通道skip拼接，SeparableBlock(88,40) |
| 解码1/2 | 24×256×256 | 与16通道skip拼接，SeparableBlock(56,24) |
| refine | 24×512×512 | 上采样后SeparableBlock(24,24) |
| 输出 | 1×512×512 logit | Conv1×1，评价时sigmoid阈值0.5 |

每个SeparableBlock包含两组3×3 depthwise→BN→ReLU6→1×1 pointwise→BN→ReLU6。上采样使用bilinear、align_corners=False。基础轻量版本上采样后直接接1×1头；refine增加全分辨率空间处理以尝试连接细弱响应，不预先保证拓扑或几何准确。

二级训练使用所有正负样本；带放回采样期望切块正负1:1，每轮1080次抽样。损失为所有图片BCE + 仅阳性图片Dice，纯负batch只计算BCE。报告按全数据累计BCE、按阳性图片累计Dice Loss，避免batch划分影响；旧Loss口径不能直接比较。

Adam，解码器初始lr1e-3、编码器1e-4；前三轮冻结编码器及BN，第4轮起联合微调。ReduceLROnPlateau监控验证Dice，patience=5、factor=0.5，最低学习率分别1e-5/1e-6。最多100轮、batch=4；至少30轮，连续15轮无超过0.002的有效提升早停，同时始终保存实际最高Dice权重。refine实际43轮结束、最佳28轮；测试开发切块Dice41.76%、Recall49.36%，阴性切块误报68.18%。

## 整图推理与重建

```text
2048×1536 RGB完整画面
  → 按固定坐标提取12个512×512块并搬运
  → 一级共享编码与3×4上下文 → 12个logits → top-6
  → 二级refine仅处理选中块（分割batch=6）
  → sigmoid≥0.5 → 回填固定坐标
  → 未选区域为背景 → 2048×1536掩膜
```

全覆盖对照绕过一级排序，对12块运行同一二级模型。当前块之间无重叠，重建是按坐标赋值，不存在已实现的重叠加权融合或旋转逆变换。一级漏掉的真实像素都成为FN，不能只评价选中的ROI。

整图无候选跳过关闭。验证集最高块分数阈值0.7时阳性Recall90%、阴性误触发60%；阴性误触发20%时阳性Recall80%。验证仅5张阴性整图、测试开发没有阴性，不足以证明安全筛帧。邻接安全扩展和分数间隔回退也没有形成可用收益，不作为当前默认策略。

## 评价、测速与可宣称范围

主要评价在完整画面累计TP/FP/FN：`Dice=2TP/(2TP+FP+FN)`、`IoU=TP/(TP+FP+FN)`、`Precision=TP/(TP+FP)`、`Recall=TP/(TP+FN)`。负图FP同样计入。无裂纹图片只要预测一个像素即为图片误报，同时另报负图像素误报比例；无负图时误报率记为不适用，不填0。

一级分别报告阳性块Recall和裂纹像素候选覆盖率，两者不能混用。对当前仅候选区域产生预测的系统，`最终Recall=候选真实裂纹像素覆盖率×已覆盖真实裂纹像素的分割Recall`；候选覆盖是上限，但块级准确率不是。

统一入口为 `scripts/benchmark_roi_cascade.py`：固定二级权重、split、batch=6、warmup=3、repeats=3，使用CUDA同步计时。范围包含图像解码、全部块准备/搬运、可选一级、选块分割、阈值与CPU重建；标注I/O和指标排除。质量只累计首遍，每遍均纳入延迟。报告保存权重与manifest哈希、设备、精度、平均/P95及allocated/reserved峰值；历史缓存本地文件、离线顺序帧不能代替实时数据流。

当前refine测试开发集全覆盖→grid top-6：Dice41.77→44.86%，Recall49.36→48.27%，平均133.00→102.20ms，候选像素覆盖96.79%。这证明当前主机上存在减块与质量/延迟折中，尚未证明相同Recall下明显提速；阴性整图误报、目标设备、能耗和几何误差均未达验收。不同二级模型、旧未预热计时、不同后端或不同精度结果必须单独标记，不能交叉拼接成收益。

## 导出与后端验收

默认质量基线为eager FP32。FP32 TorchScript导出脚本当前主要验证CPU单合成输入，不能自动证明CUDA、多输入或batch=6一致。历史单块基准与级联指标接近只保留为性能/质量观测，不能据此把差异归因为阈值边界。

2026-11-17独立模型复验：CPU三个固定随机输入和一个真实块最大差均0；CUDA后续输入最大logit差0.28264/0.28641/0.91796，严格assert_close失败，均无非有限值，本次二值掩膜差异为0。样本很少、batch=1，不能推断整个数据集的输出一致。原因未确认，未通过CUDA部署验收。

FP16独立导出经历直接CUDA trace、CPU FP32 trace后half、关闭in-place、多输入与保存重载校验；最终仍失败，文件保留在 `deploy/independent_fp16_attempts/`。旧元数据中的passed仅反映当时检查范围，不能视为当前验收状态。运行时half、eager FP16、独立FP16文件分别记录，不能混淆。ONNX、INT8与目标后端尚未验证。

后续导出门槛：用独立eager/部署模型，固定后端配置，保存重载后测试多输入、多batch和真实正负样本；记录有限值、logit误差与阈值掩膜差异，执行预先明确的容差并报告失败，不降低断言来通过。通过后再进行完整级联和目标设备测试。文档中的默认基线不等于已经提供自动选择后端的产品配置。

## 适配原则、后续实验与停止条件

困难集v3已有60个阳性块/27组和6类contact sheet，覆盖低像素量、贴边/接缝代理、一级漏选、二级低Recall和排序分歧。已有视觉抽样，但完整人工形态审核未完成。自动代理只作为索引，不能直接作为真实跨块、弯曲或分叉辅助标签。

下一轮先完成原分辨率人工复核、独立阴性/外部留出和场景泄漏检查，再按失败类型决定监督或二级适配：低像素块漏选检查证据与标签；已选块仍漏检检查二级细化与标注；接缝连续性问题需先确认同一裂纹的归属。当前不预设必须换某种主干或重复局部池化分支。

每次实验必须说明数据协议、针对的失败样例、标签/增强、结构与参数量、损失/采样、最佳轮次、验证和测试开发结果、冻结二级的完整级联、延迟/显存及停止理由。不收敛、NaN和指标下降也保留。同一路径最多三轮有明确假设的尝试，不要求用满三轮；无收益可提前停止，不能仅改名、调阈值或反复搜损失权重继续同一路线。

若未来重启任意框/旋转框，先验证原分辨率裂纹候选覆盖，再做水平框对照。OBB需同步定义多区域标签、角度周期、匹配/NMS、扩框、真实旋转采样和逆变换；不能只增加角度输出。长条框角度误差引起端点横向偏移约 `(L/2)sin|Δθ|`；旋转插值可能影响宽度，必须另测。大ROI按原尺度切块、小ROI补边并移除填充，重叠规则在验证集冻结。这些均未实现为当前主线。

理论上固定网格级联耗时为 `T_rank(12块)+ΣT_seg(选中批次)+T_prepare/reconstruct`；节省二级计算必须超过一级和调度开销。未来筛帧可用 `p=q·r+(1−q)·f` 描述触发率，但降低Recall也会降低p，不能当有效优化。旋转框几何面积更小也不意味着固定512输入的单次计算更少，应测实际块数与端到端时间。

目标设备、最低Recall、最低关注裂纹宽度、平均/P95延迟、内存预算及几何容差尚待确定。没有物理标定时只能报告像素尺度几何，不能声称毫米级准确度或直接判断结构危害。阶段计划与依赖关系见[迭代计划](iteration_plan.md)。
